UVM Interview Questions and Practice

UVM interviews are less about memorising class names and more about understanding how transactions move through a verification environment and how the environment detects incorrect DUT behaviour.

Core UVM concepts

Sequence items and sequences

Understand how transaction objects represent stimulus and how sequences generate that stimulus. Be able to explain the relationship between a sequence, sequencer and driver.

Drivers and monitors

A driver converts transactions into pin-level activity. A monitor observes DUT signals and reconstructs transactions without driving the interface. Know why keeping these responsibilities separate matters.

Scoreboards and reference models

A scoreboard compares expected behaviour against observed behaviour. A reference model can predict the DUT output from the same transaction-level inputs, making functional checking systematic rather than dependent on manual inspection.

Analysis ports

Know how monitors publish observed transactions and how subscribers such as scoreboards consume them. Interviewers may ask how multiple components can receive the same stream.

Questions worth practising

  • What is the role of a UVM driver?
  • How does a monitor differ from a driver?
  • What does a sequencer do?
  • How would you design a scoreboard?
  • Why use a reference model?
  • How does an analysis port connect a monitor to checking components?
